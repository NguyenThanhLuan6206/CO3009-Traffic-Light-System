# Teamwork and Source Code Management Rules

## 1. Commit Accounts
* The commit history serves as the basis for assessing each member's contribution. 
* Do not share accounts under any circumstances; each member must commit code using their own personal GitHub account.

## 2. Naming Conventions
* **File names:** Use lowercase letters joined with underscores (e.g., `fsm_automatic.c`).
* **Function names:** Follow the `<module>_<action>` syntax (e.g., `button_read()`, `traffic_set_state()`).

## 3. Commit Message Rules
* Commit frequently.
* Each commit must represent **one meaningful change**.
* Messages must be clear and accurately reflect the work done (Standard example: `scheduler: add one-shot task support`).
